# 金额计算常见陷阱

本项目（price-calc）容易踩的金额计算坑，逐条排查：

## 1. 先取整再折算

把价格先 `Math.floor` 成整数元再算折扣，会吞掉分位：

```
calcPrice(99.9, 0) 期望 99.9，得到 99
```

处理金额先按「分」运算，最后再统一取整，而不是中间就取整。

## 2. 浮点精度

折扣率用 `x / 100` 再乘，某些小数会留下 `0.0000000002` 级别的尾差；
涉及金额应避免中间结果直接相乘再相除，尽量用整数分做全程。

## 3. 负数 / 超范围

折扣 `< 0` 或 `> 100`、价格 `< 0`，应在入口抛出清晰错误，
而不是静默返回一个奇怪的结果。

## 4. 验证姿势

- 先跑最小复现脚本，锁定一个失败用例；
- 修完先跑复现脚本，再全量 `npm test`。
